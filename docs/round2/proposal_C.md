# Proposal C: the salesperson's path, from saying the job to sending the quote

Builder C · round 2 · 2026-11-19 · the company is PWI / PWI Corp.

**The core idea: the spec is the quote.** It is saved on the revision (`doc.spec`). Each assumption is a chip. Tapping a chip changes the spec, rebuilds and reprices. Line editing becomes the power-user basement.

From 9 steps to 4: **say the job, tap the link, review the chips, tap Send.**

---

## 1. The skill conversation (full SKILL.md v2 in Appendix)

- **Fewest questions.** Ask only for missing blockers: product type, capacity, span, runway length, any height. Ask them all in one round. Everything else gets a default and becomes a chip: voltage 460V/3, UL and HL manual, M and GM motorized.
- **Inference.**
  - Model codes: `FSTRGM5` means GM, 5 t.
  - A city becomes estimated one-way miles.
  - "30 by 80" means span × runway.
  - "tall" means `overallHeightFt`; only "under hook" means hook height.
  - "pink columns" becomes a custom-paint field.
  - Customer and contact come from the conversation.
- **Confirming.** A one-line read-back, then the link. No "is that right?". Fixing on Review is one tap; another chat round costs more.
- **Voice.** Short sentences, loose answers ("four sixty"). Never read JSON or URLs aloud.
- **Several items.** `items[]` with a `tag`. "Two of them" means `systems: 2`.
- **A link instead of a paste.** `make_link.py` (in the skill) turns the spec into `…/#/import?s=<base64url>`. The hash never reaches a server. Fallback: the JSON block plus **Ctrl+V anywhere** in the app, or a big "Paste from Claude" button on the phone.

## 2. Review screen (new default view of a quote)


- **Summary.** Generated by `summarize(spec, priced)` (pure, portable).
- **Chips.**
  - Solid means the rep said it; dashed means inferred or defaulted.
  - A tap opens a popover (bottom sheet on a phone) with one-tap alternatives ("Standard · Custom color · Primer") or a number field.
  - A change patches the spec, rebuilds, reprices and autosaves.
  - The builder returns `assumptions: {field, label, value, source, choices?}[]` in place of free-text `notes`.
- **Check these.**
  - Builder judgment notes, lint errors and approval flags.
  - Each has one action (Confirm, Pick hoist, Ask manager). Red blocks Send; amber needs a ✓.
- **Price.** A big total and margin against the target, colored. The eye icon hides internals for screen-sharing and stays hidden on reload.
- **Send.**
  1. Builds the PDF.
  2. Phone: `navigator.share` with the file attached. Laptop: downloads the PDF and opens a `mailto:` draft (no attachment until server email).
  3. Asks "Did it go out? Lock R0".
- **Details.** Line items grouped by category with subtotals, read-only. An "Edit lines" button goes to the editor.

## 3. Editor simplification (the power features stay)

- **Remove:**
  - the per-row Category select (the row's group sets it; a row menu offers "Move to…")
  - the disabled "Document" field (it becomes a pill)
  - "Main product" (it lives on each item)
  - the Save button (autosave after 2 s with the existing `doc_version`; a conflict shows a banner)
- **Group:**
  - Lines fold by category with subtotals.
  - Qty and Sell are always shown. A **Cost view** toggle adds cost, markup and unit sell.
  - Freight, pre-use, discount, tax and PV fold into "Adjustments", whose header shows only the non-zero values.
  - Wording folds to a preview with a lint count.
- **Replace QuickAdd** (9 buttons, 4 forms) with **one "+ Add" search box** over shapes, parts, vendor parts, labor ops and rate items. It parses `W14x43 4 @ 30`. `/` focuses it.
- **Right panel:** one primary button that follows the state (Send, then New revision, then Mark won). Everything else goes in a `⋯` menu.

## 4. Re-quoting by talking

- The skill gives every job a stable `id`. "Make it 100 feet long" makes Claude send out the **whole** spec again with the same `id` plus `rev_note`. It never sends a partial diff.
- On import, the app looks up `quotes.spec_id`:
  - **Sent or locked:** calls `revise`, then saves, which makes R1.
  - **Draft:** updates it in place.
- A banner, built by diffing spec and price: "Updated from Claude: runway 80' → 100' · +$6,140 · Undo".
- `auto:true` lines are rebuilt and hand-added lines kept. If built lines were hand-edited, it asks "Keep my edits / Use new build".
- **Later:** an MCP connector runs the engine on the server, so Claude replies "Done, R1 is $148,520" with no link.

## 5. Polish

- **Update banner.** The build writes `version.json`; `useAppVersion.ts` checks it on focus and every 5 minutes, then shows "New version ready · Reload" (automatic on the next route change if nothing is unsaved). Add no-cache for it in `netlify.toml`. This fixes the missing-paste-box incident.
- **Empty states.** Quote list: "No quotes yet. Tell Claude about the job, then tap its link", plus Paste and Start blank. Check these: "Nothing to check ✓". No search match: "Add custom line".

## Risks

- Claude cannot base64-encode reliably by hand, so the script does it. The app checks the decoded JSON and shows "Link damaged — paste instead".
- Long wording makes long links. Keep that wording short.
- The same link opened twice is deduplicated by `spec_id`. A new job in the same chat must get a new `id`. The app shows "This will change Q-26-0014 · Make new instead".
- Paint, travel, lift and height chips need engine support. Until then they appear as "Check these" items, never silently dropped.

## Appendix: SKILL.md v2 (full text)

````markdown
---
name: pwi-quote
description: Turn a spoken or typed PWI job description (freestanding crane, bridge, gantry, monorail, jib, mezzanine, stairs…) into a one-tap link that builds the quote in the PWI quote app. Use when a PWI salesperson describes a job to quote, or asks to change a quote from earlier in the chat.

# PWI Quote

The company is PWI or PWI Corp. Never use any other company name.

A salesperson tells you about a job, by typing or by voice, sometimes with a drawing. You turn it into a **spec** and hand back a **link**. The link opens the PWI quote app (https://pwi-quotes.netlify.app), where the quote is built, priced and ready to send. The rep corrects small things there with one tap, so **speed beats certainty here.** Never hold up the link to confirm something that has a sensible default.

## Steps

1. **Pull out everything they said**, using the inference rules below.
2. **Ask only if a blocker is missing.** The blockers are:
   - product type
   - capacity
   - span
   - runway length
   - a height (any kind)

   Ask in ONE round, with every missing blocker together. Use AskUserQuestion when you have it, with the most common answer first. Otherwise ask one short spoken-style sentence: "Two things: what capacity, and how long is the runway?" Never ask about anything that has a default.
3. **Build the spec** (format below). List every field you inferred or defaulted in the item's `assumed`.
4. **Make the link.** Run `make_link.py` with the spec JSON on stdin and give the URL it prints. If you cannot run code, output the spec as one fenced `json` block and say: "Copy this and paste it anywhere in the PWI Quotes app."
5. **Read back in one line**, then the link. Example: "5-ton FSTRGM, 30 × 80, 20' overall, radio, 460V, pink columns, installed in Milwaukee (~165 mi). [Open quote]". Do not ask "is that right?". The rep fixes it in the app.

Voice: keep every sentence short. Never read JSON, field names or URLs aloud. Say "Your quote link is in the chat." Accept loose answers such as "four sixty", "yeah, install it" or "two of them".

## Inference rules

- **Model codes.** FSTR + series + tons:
  - `UL` is Ultra-Lite (default manual).
  - `HL` is Hyper-Lite (default manual).
  - `M` is motorized top running.
  - `GM` is girder motorized.

  For example, `FSTRGM5` means GM, 5 t, motorized. A bare "FSTR" with no series: use GM for 5 t and up and M below that; mark it assumed.
- **Size.** "30 by 80" means span 30, runway 80 (smaller number first). Feet and inches become decimals (20'8" = 20.67).
- **Height.** "under hook", "hook height" or "HUH" goes in `hookHeightFt`. "tall", "high", "overall" or "top of steel" goes in `overallHeightFt`. "Ceiling is 22" means `overallHeightFt` 21 (leave 1' clearance); mark it assumed.
- **Location.** A city means one-way driving miles from Nappanee, IN. Round to 5 and mark it assumed. "install in X" means install is true. "ship", "customer installs" or "no install" means install is false. No location at all means install is true; mark it assumed.
- **Paint.** A color word ("pink columns", "safety yellow", "match their blue") gives `paint: {finish:"custom", color, parts}`, where parts is "all", "columns", "bridge" or "runways". "Primer only" gives `finish:"primer"`. "Galvanized" gives `finish:"galv"`. Otherwise use standard paint; do not mark it assumed.
- **Defaults** (always list them in `assumed` when used):
  - voltage 460V/3
  - control: radio when motorized, pendant when manual
  - 1 system, 1 bridge, 1 hoist
  - no pre-use inspection
  - travel and equipment `"auto"` (the app works out crew, nights, hotel, per diem and lift from miles and height)
- **Equipment.** "They have a lift" or "customer provides lift" gives `equipment:"customer"`. A named machine ("telehandler", "boom lift") gives `equipment:["Rental 10K Telehandler"]` and similar.
- **Customer.** Capture the company, contact name, email and phone whenever they are said. If none is said, leave `customer` out. Never ask for it; the app asks.

## Several products

Use one spec with several `items`, each with a short `tag` ("Bay 3 crane", "Mezz"). "Two identical cranes" is ONE item with `systems: 2`.

Bridge, gantry, monorail, jib, mezzanine, stairs, VRC and fall protection do not have automatic builders yet. Include each one with its `type`, the dimensions said, and a short `wording` block in PWI spec style:
- `(qty) - MODEL TITLE`
- General Specs
- one line per component

The app keeps that wording and flags the lines as needed.

## Changes later in the chat

When the rep says "make it 100 feet long", "drop the install" or "add a second hoist":
1. Output the **whole** spec again, with the SAME `id`, the change applied, and `rev_note` describing it ("Runway 80' → 100'").
2. Make a new link.
3. Read back only the change.

Never send a partial spec. If they start a DIFFERENT job in the same chat, give it a new `id`.

## Spec format

```json
{
  "pwi_quote": 2,
  "id": "milw-gm5-7k2p",
  "rev_note": null,
  "customer": { "name": "Acme Mfg", "contact": "Joe Smith", "email": "joe@acme.com", "phone": null },
  "project": "FSTRGM5 Crane System",
  "location": "Milwaukee, WI",
  "items": [
    { "tag": "Crane 1", "type": "freestanding", "series": "GM", "capacityTons": 5,
      "spanFt": 30, "runwayOalFt": 80, "overallHeightFt": 20,
      "bridgeDrive": "motorized", "voltage": "460V/3", "control": "radio",
      "paint": { "finish": "custom", "color": "pink", "parts": "columns" },
      "install": true, "miles": 165, "travel": "auto", "equipment": "auto",
      "systems": 1,
      "assumed": ["voltage", "miles", "travel", "equipment"] }
  ]
}
```

- `id` is a short slug plus 4 random characters, made once per job.
- Optional freestanding fields: `trolley`, `hoistsPerBridge`, `bridgesPerSystem`, `columnsPerSystem` (only from a drawing), `collisionAvoidance` (2+ bridges on one runway), `bracedToBuilding`, `liftFt`, `preUseInspection`.

## make_link.py

```python
import base64, json, sys
spec = json.loads(sys.stdin.read())
s = base64.urlsafe_b64encode(json.dumps(spec, separators=(",", ":")).encode()).decode().rstrip("=")
print("https://pwi-quotes.netlify.app/#/import?s=" + s)
```
````
