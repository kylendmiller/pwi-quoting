# Review 1: correctness, margin, security

B's harness reproduces its table when re-run. Edge probes: `/tmp/r1/edge.ts`.

## Blockers

**1. The approval threshold comes from the client.** `suggestedInstallHours` lives in `doc`, which `save` stores as sent and `send` re-prices (`manual.ts:103`). A rep can POST `save` with suggested = quoted, and the flag disappears.

Chips move "suggested" by design: Lowering miles, choosing a 2-man crew, travel "local" or "customer lift" lowers price and threshold, no flag. B also returns `suggestedInstallHours: 0` when install is off (−$19.9k). (not null), so a hand-added site-labor line is never flagged.

*Fix:* store `doc.spec` and have `save` and `send` recompute the suggestion on the server. Add an `INSTALL_SCOPE_REDUCED` flag when install, miles, crew, travel or equipment is set below what the builder would derive.

**2. B has no build envelope, so it underprices silently.**
- **29523** (a GM5 with 2 bridges, looks ordinary): **−43% base, −49% site hours, −72% freight, and no note at all.** The +5% median hides this.
- **25 t:** a $209k quote with no warning. The sold 28970 was $477k.
- **Past the end of the charts** the code silently uses a default shape. With an 80' bay the runway is W21x101, and **the price drops**.
- "Crane service" and "end truck not found" go only into `notes`, which block nothing.

*Fix:* a hard envelope (≤10 t, bay ≤30', span and height inside the charts, no specials). Outside it, raise a blocking `OUT_OF_ENVELOPE` flag.

**3. A missing `miles` zeroes freight, travel and lodging silently.** `miles ?? 0` treats the job as local with $0 freight, and no chip appears. That is $4.4k on the Milwaukee job and $25k+ at 1,000 mi.

*Fix:* require miles whenever the job is installed or shipped, and schema-validate the spec (min/max on every number).

**4. C's Send shares the PDF before the server gate runs.** The PDF goes out through share/mailto, and only then does the app ask "Did it go out? Lock R0". If the rep answers No, the quote stays editable after the customer has it.

*Fix:* call `send` first, so the revision locks, then render the PDF from the locked revision. Watermark any unlocked revision "DRAFT".

## Fix before ship

5. **No ownership checks.**
   - `save`, `send`, `revise`, `win` and A's `build` with a `quote_id` accept any quote from any sales user.
   - `header.contact_id` is not checked against the quote's customer.
   - Managers can approve their own quotes.

   *Fix:* require `salesperson_id = uid` or a manager. Check that the contact belongs to the customer. Block self-approval.
6. **An approval covers only the flag's two numbers.** After an install approval, the rep can cut steel, zero a markup (only a warning), raise the discount, or delete travel and equipment lines. Nothing flags low GM% or a high discount.

   *Fix:* add total and GM% to `covered_hash`, and add `GM_BELOW_FLOOR` and `DISCOUNT_ABOVE_X` flags.
7. **C's `spec_id` can update another quote.** The id is a slug plus 4 random characters chosen by the LLM, so it has low entropy and can collide. A match updates a draft in place.

   *Fix:* use A's `uuid4` ref (generated by the script), scope the lookup to the caller, and always show the confirm card.
8. **A's customer match.**
   - Treating a score ≥0.9 as "exact" auto-attaches near-twins (Inc vs LLC, the same name in another state).
   - A score below 0.45 ("Acme Fab" vs "Acme Fabrication Inc") creates a duplicate.

   *Fix:* count as exact only an equal normalized name in the same state. Always show city and state. Never create a customer without the rep's tap.
9. **C's autosave.**
   - Two devices autosaving every 2 s loop on 409s; `quote_line_facts` is rewritten outside a transaction.

   *Fix:* on a 409, stop autosaving and show the banner; never reload over the rep's edits. Make `persistRevision` a single SQL rpc.
10. **B's calibration is in-sample.**
    - Rules were fitted on the same 5 jobs; ±15/25% tests on them pass by construction.
    - Plate is still off by 40–52% (median absolute error).
    - The nearest-job lookup lost in leave-one-out (13% vs 9%), **yet the code defaults to it** (`steelSource === 'chart' ? null : nearestSold()`), which contradicts B's own text.
    - It borrows girders/columns/runways from smaller sold geometry, so it errs toward undersized steel.

    *Fix:* make the chart the default. Borrow only from sold jobs with geometry ≥ the new one. Use holdout jobs from the 97-job extract.
11. **Defaults that bias low.**
    - **Single girder up to 10 t,** although the sold GM5 job (29523) was double girder. Double is worth +$12–22k. Make it an amber "Confirm girder" for GM ≥5 t.
    - **10 t headroom is 3' against 4' at 5 t,** which is backwards. On a hook-height spec the 10 t system comes out shorter, and the quoted hook height can't be reached.
    - **Paint** ignores the <18" booth limit; **freight** has no minimum ($930 for 165 mi).

## The banned name

The literal string appears in several places:
- `skill/pwi-quote/SKILL.md:10` (in Claude's context)
- `db/seed_core.sql:22` (visible in Admin)
- the lint message (on screen and in the 422)

Lint checks `doc.wording` only. Curly-apostrophe and no-apostrophe spellings slip through. It skips every other string in the PDF and email.

*Fix:* store a normalized letters-only pattern, use a generic message, and scan every string that goes into the PDF or email. In SKILL.md use C's line: "PWI or PWI Corp. Never use any other company name."
